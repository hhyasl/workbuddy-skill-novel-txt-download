# 排障速查

## 状态码 / 现象对照

| 现象 | 真实原因 | 处置 |
|---|---|---|
| curl 返回 `000`，耗时 5~20 秒 | 连接被 reset（频控），**不是** DNS/网络故障 | 重试 + 退避；降低并发；加长间隔 |
| curl 返回 `000`，耗时 0.1 秒 | 沙箱代理 `127.0.0.1:1950` 不存在 | 加 `--noproxy '*'`（curl）或用 `ProxyHandler({})`（Python） |
| HTTP 403 + 一段固定 HTML | 站点风控 / Cloudflare 验证 | 换源；或用 WebFetch 通道（但 WebFetch 也常卡在验证页） |
| HTTP 404，body 很小 | 章节不存在 / URL 模板错 | 核对 probe 输出的 `chapter_url` 与 `book_id` |
| HTTP 200 但 body 0 字节 | 接口需签名（番茄正文接口） | 放弃该接口，换源 |
| HTTP 200 但 body 仅 1~2KB | 被拦截或跳验证页 | 检查是否含正文特征（`<p>`），换源 |
| 进程静默退出、无任何输出 | 沙箱 SIGTERM 前台网络任务 | 改用后台任务运行 |
| 抓回来正文为空 / 只有推荐书单 | 抓到了外层容器或书单容器 | 核对 `content_class`，必须是正文容器 |
| 章节只有一半 | 分页没跟上 | 核对 `paged_url` 模板与 `next_paged_regex` |

## 抓取速度参考

| 并发 | 速度 | 失败率 | 结论 |
|---|---|---|---|
| 1 | ~5 章/分 | 低 | 太慢 |
| 4 | ~35 章/分 | 低 | 稳 |
| 8 | ~50 章/分 | 偶发 | **推荐**，配合重试 |
| 16+ | 表面更快 | 高 | 不推荐，reset 变多反而更慢 |

整本 1152 章参考耗时：8 并发约 20~30 分钟。

## 章节乱序

**症状**：输出里第 500 章突然变成"第 560 章"，末尾多出几章作者致谢。

**原因**：抓取站的 URL 序号 ≠ 真实章节号。站点会插页、跳号、把更新的章节前置。

**处置**（已经在 `merge` 里实现）：
1. 加载官方目录（`catalog.json`），得到权威的**有序标题列表**
2. 把抓回来的章节按**归一化标题**（去掉所有空白）建索引
3. 按目录顺序逐个标题配对输出，重复标题用 FIFO 队列
4. 配不上的记入"缺失"，缓存里多出来的记入"多余"

**绝不要**按站点 URL 序号排序输出。

## 缺章 / 重复章节

用 `verify` 判断：

```
目录章节 1152   缓存章节 1152
目录有缓存无: 0 []      ← 缺章
缓存有目录无: 0 []      ← 多余
空章节: []             ← 内容为空
```

- 「目录有缓存无」> 0 → 该章抓失败，重跑 `fetch`（有缓存会跳过已完成的，只补缺失的）
- 「缓存有目录无」> 0 → 站点有目录外的章节，通常是番外/致谢章，可以保留也可以丢弃
- 「空章节」> 0 → 抓到了错误页，检查 `content_class`

## 编码

| 场景 | 用哪个 |
|---|---|
| 电脑 / 现代手机 / 脚本处理 | UTF-8 版（`书名.txt`） |
| 老手机 / 老阅读器 / 十几年前的设备 | GBK 版（`书名-GBK.txt`） |

- 两版内容**完全一致**，只是字节排布不同（GBK 中文 2 字节、UTF-8 3 字节，GBK 版约小 1/3）
- 用 GB18030 编码写 GBK 版（GB18030 是 GBK 超集，能覆盖生僻字）
- 严格只认 UTF-8 的工具（部分 LaTeX 链、某些 EPUB 转换脚本、老 pandoc）遇到 GBK 会报错或转出乱码
- 老设备默认按 GBK 解码，看到 UTF-8 会显示"锘斤拷"或方块
- 两个版本都不带 BOM；换行统一 CRLF（Windows 习惯，手机阅读器也认）

## 沙箱网络任务清单

1. **后台运行**：`run_in_background: true`，前台会被 SIGTERM 静默杀掉
2. **禁用代理**：环境变量 `http_proxy/https_proxy` 指向不存在的 `127.0.0.1:1950`
3. **Windows 无 `stdbuf`**：改用 `python -u`；`tee` 管道可用但输出会延迟
4. **长任务配缓存**：沙箱可能随时 SIGTERM，磁盘缓存 + 断点续跑是唯一可靠做法
5. **GitHub raw 下载**要 `curl -x http://127.0.0.1:10909`（直连不通），大文件加 `-C -` 续传
